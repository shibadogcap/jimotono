# Load-balancing検証（μ感度＋勾配伝播確認）— feat/p3/lb-check

- 性質：文書＋実行のみ。API破壊なし、fail-closed不変、既存tol不変、ctest全pass（17/17）。コミットしない。
- 目的：μ=0.1で挙動不変との prior 観測が感度不足か実装バグかを分離する。
  μを0/0.01/0.1と振り、ルーター分布（amax/entropy/drop）が変わるか短条件で比較する。
  変わるなら感度不足、変わらないなら実装バグとして修正する。
- ビルド：同wt内 `build-lb/` のみ（`cmake -S . -B build-lb`＋`cmake --build build-lb`）。
- 実行：すべて逐次・単一プロセス。重負荷は短条件＋500 step走行のみ。

## 1. 条件（短条件μスイープ）

- `build-lb/train_tinystories --data data/tinystories_head16M.txt --steps 30 --batch 4 --seq 128（T=512） --val-every 100 --patience 0 --max-val-pairs 2000 --aux-weight {0,0.01,0.1} --moe-batch` を逐次各1回。
- 同一シード・同一データ順（seq連続スパン決定論的サンプリング・決定論的初期化）のため、同一stepのTX/TYはμ間で同一。差は重み軌道（μ経由）の反映である。
- 実行前後 `uptime` 確認（開始時 load 2.52/2.50/2.27、重負荷プロセスなし。OpenChamber UIのみ常駐）。
- ログは `build-lb/lb_mu{0,001,01}_stdout.log`＋`lb_mu{0,001,01}_stderr.log`（各30行 `train_ts_step`）に保存（本wt限り）。

## 2. 結果：勾配はルーターに伝播している（実装バグなし）

- step1は3条件で同一（fwdが更新前で同一のため。`ce=5.538403`、`aux=0.582021`、`ent=0.599785`、`dropped=159/2048=7.7637%`、`amax=253.5`が一致。`train_ce` のみμ項で差：5.538403/5.544223/5.596605 = ce+μ·aux と整合）。
- step10：drop μ0 6.40% / μ0.01 6.01% / μ0.1 4.54%。amax 242.5/230.5/235.0。既に分離開始。
- step20：drop μ0 7.76% / μ0.01 5.18% / μ0.1 3.86%。amax 263.0/243.0/230.0、ent 0.592/0.622/0.636。
- step30：drop μ0 7.28% / μ0.01 6.93% / μ0.1 1.56%。ent 0.600/0.606/0.667、amax 252.5/244.0/188.0、rmax 1.973/1.906/1.469。
- 後半10平均（steps 21–30）：drop 6.89%/5.41%/2.02%、ent 0.613/0.620/0.662、amax 239.1/238.1/203.6。
- よってμを振るとルーター分布（amax/entropy/drop）は明確に変わる。特にμ=0.1は30 stepsでdropを約1/4（7.3%→1.6%）、amaxを約25%削減（252.5→188.0）、entropyを上昇（0.600→0.667：一様化）させる。
- 配線の目視確認：`ts_aux_grad_apply()` がT一括路（single/batch両路）の `m->G` のWgate部へ加算する構造であり、μ=0時早期return、μ>0時 `g=μ·E·f_e/K` 経由のヤコビアン加算を行う。step1の `train_ce=ce+μ·aux` の整合および上記分布変化と一致するため、勾配伝播は実装通りである。

## 3. prior観測（§10.5「μ=0.1同傾向」）との整合

- §10.5の短感度（20 steps、μ=0.1でμ=0.01時と同傾向）は、窓が短く分離の過渡域（本測定でもstep10–20はμ0.01とμ0.1の差が1–2pp級と小さい）を見ていたための感度不足である。
- 本測定では30 stepsまで延ばすとμ0.1の整流が顕在化する（step21で2.09%、step28–30で0.6–1.6%）。時定数が20 steps超である。
- seq==1 legacy路は `ts_aux_grad_apply()` を呼ばない（auxログのみ。コード内コメント通り。G2はT路同士で比較するため公平）。legacyでμを振っても不変なのは仕様通りであり、本検証の対象外である。T路でのμ効果は本節の通り確認済みのため、LB修正（実装バグ修正）は不要である。

## 4. 判定：感度不足（実装バグなし）。LB修正なし

- 判定ルール（本タスク）：変わるなら感度不足、変わらないなら実装バグとして修正。
- 本結果は変わる（μ=0.1で強く整流）ため、**感度不足（時定数要因）**と判定し、実装修正は行わない。
- μ引上げ・cap変更等の設計改訂は本タスクでは行わない（記録のみ）。

## 5. 参考：seq==1 legacy single vs batch（drop=0区間bit一致の証拠）

- `batch=64 seq=1`（T=64相当の逐次路）で single vs `--moe-batch` を30 steps比較したところ、全30 stepsでdrop=0、かつ `ce` が6桁表示で完全一致（相対差0.00e+00）した。
- これはG2文書（§5.4改訂）の「drop=0区間bit一致」の実証であり、乖離onsetが初drop（T=512ではstep1の159/2048=7.76%から乖離開始：single ce=5.538190 vs batch ce=5.538403）であることと対をなす。
